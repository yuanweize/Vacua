# Declarative Rule Format (v1)

Project Reclaim uses declarative TOML data files for defining storage classification rules. **Rules are strictly data, never executable scripts or shell commands.**

---

## 1. Schema Specification

A valid rule file has the extension `.toml` and follows this schema:

```toml
schema_version = 1
id = "apple.xcode.derived-data"
name = "Xcode DerivedData"
description = "Intermediate build products, module caches, and index data generated by Xcode compilations."
category = "build_artifact"
risk = "safe"
reconstructable = true
rebuild_consequence = "Next compilation in Xcode will rebuild necessary index and build products."

[references]
author = "Project Reclaim Maintainers"
docs = "https://developer.apple.com/documentation/xcode"

[[matches]]
# Path glob relative to user home directory or absolute path
path = "~/Library/Developer/Xcode/DerivedData/*"
file_type = "directory"

[[guards]]
# Ensure xcodebuild or Xcode isn't actively compiling into this location
type = "process_not_running"
value = "xcodebuild"

[[guards]]
type = "process_not_running"
value = "Xcode"

[[guards]]
# Optional minimum staleness guard (in days)
type = "min_age_days"
value = "0"
```

---

## 2. Supported Categories

- `cache`: Ephemeral caches that can be discarded without operational impact.
- `log`: Log files, diagnostic crash reports, and system telemetry records.
- `temporary`: Temporary scratch files intended for short-term lifespan.
- `build_artifact`: Compiler outputs (`DerivedData`, `target/`, `build/`, `dist/`).
- `package_manager_cache`: Package manager download and registry caches (`cargo`, `npm`, `pip`, `homebrew`).
- `simulator_data`: iOS/watchOS/tvOS simulator devices, unavailable runtimes, and system images.
- `container_data`: Docker/Podman build cache, dangling layers, unused containers.
- `installer`: Downloaded `.dmg`, `.pkg`, or update packages.
- `application_leftover`: Remnants left behind by previously uninstalled applications.
- `duplicate`: Verified identical copies of files.
- `unknown`: Unclassified items (never auto-cleaned).

---

## 3. Supported Guards

Guards prevent rules from triggering when an environment is actively using the target:

1. `process_not_running`:
   - Checks the system process table (`sysinfo`). If any active process matches the name, the rule matching is rejected.
2. `min_age_days`:
   - Checks the target's `mtime` or `atime`. If the file was modified within the specified number of days, the rule does not apply.
3. `path_exists`:
   - Requires a secondary companion path to exist (e.g. verifying an uninstalled application is truly absent).
